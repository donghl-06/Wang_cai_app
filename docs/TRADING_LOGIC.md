# 旺财回测平台 - 交易逻辑解析

## 📖 概述

旺财回测引擎采用**事件驱动**架构，基于真实逐笔行情数据重建订单簿，并在其中插入用户的虚拟订单进行撮合。

## 🕐 交易时段

引擎完整模拟 A 股交易时段：

| 时段 | 时间 | 说明 |
|------|------|------|
| 开盘集合竞价 | 09:15 - 09:25 | 撮合开盘价 |
| 连续竞价（上午） | 09:30 - 11:30 | 实时撮合 |
| 连续竞价（下午） | 13:00 - 14:57 | 实时撮合 |
| 收盘集合竞价 | 14:57 - 15:00 | 撮合收盘价 |

## 🏗️ 订单簿重建

引擎根据逐笔委托（csord）和逐笔成交（cstra）数据，实时重建真实的订单簿状态：

```
┌─────────────────────────────────────────────┐
│              订单簿 OrderBook               │
├─────────────────────────────────────────────┤
│  卖盘                                       │
│  ├─ 8.05 (10档)  [历史订单] [历史订单]      │
│  ├─ 8.04 (9档)   [历史订单]                 │
│  ├─ ...                                     │
│  └─ 7.96 (卖一)  [历史订单] [用户订单]      │
├─────────────────────────────────────────────┤
│  买盘                                       │
│  ├─ 7.95 (买一)  [历史订单] [用户订单]      │
│  ├─ 7.94 (买二)  [历史订单]                 │
│  ├─ ...                                     │
│  └─ 7.86 (10档)  [历史订单]                 │
└─────────────────────────────────────────────┘
```

## 🔄 虚拟订单撮合机制

### 核心原则

1. **虚拟订单**：用户通过策略下的订单
2. **历史订单**：从真实行情数据重建的订单
3. **撮合规则**：价格优先、时间优先

### 四种撮合场景

```
场景1: 用户订单 vs 历史订单 → ✅ 虚拟成交
场景2: 历史订单 vs 用户订单 → ✅ 虚拟成交  
场景3: 用户订单 vs 用户订单 → ❌ 不成交
场景4: 历史订单 vs 历史订单 → ✅ 真实成交（用于重建订单簿）
```

### 虚拟成交特点

| 特性 | 说明 |
|------|------|
| **同步模式** | 订单碰到对手盘立即成交，无网络延迟 |
| **无市场冲击** | 虚拟订单成交不影响历史订单簿状态 |
| **价格优先** | 按最优对手价成交 |
| **时间优先** | 同价位按订单进入时间排序 |

## 📊 撮合流程详解

### 连续竞价撮合

```
用户下单 (买入 100股 @ 7.96元)
    │
    ▼
检查订单簿卖一价
    │
    ├─ 卖一价 ≤ 7.96 → 立即成交
    │   └─ 成交价 = 卖一价（对手价成交）
    │
    └─ 卖一价 > 7.96 → 挂单等待
        └─ 等待有历史卖单 ≤ 7.96 时成交
```

**代码逻辑**（简化）：

```cpp
// 用户买单主动成交历史卖单
if (user_order.price >= best_ask_price) {
    // 立即成交，成交价 = 对手价
    execute_trade(user_order, best_ask_price, volume);
}
```

### 成交价格规则

| 场景 | 成交价 |
|------|--------|
| 用户订单主动成交 | 对手盘最优价 |
| 历史订单碰到用户订单 | 用户订单价格 |

## 🎯 集合竞价逻辑

### 开盘集合竞价 (09:15 - 09:25)

1. **09:15-09:20**: 可下单可撤单
2. **09:20-09:25**: 可下单不可撤单
3. **09:25**: 撮合确定开盘价

**开盘价计算**：
- 使成交量最大化的价格
- 高于该价格的买单和低于该价格的卖单全部成交

### 收盘集合竞价 (14:57 - 15:00)

- 只能下单不能撤单
- 15:00 统一撮合确定收盘价
- 算法与开盘集合竞价类似

## ⚡ 同步模式说明

旺财引擎采用**同步撮合模式**：

```
时间线：
T0: 策略收到 Tick 事件
T0: 策略返回下单指令
T0: 引擎处理下单
T0: 检查是否可成交
T0: 如果可成交，立即执行
T0: 触发 onTradeCallback
```

**特点**：
- ✅ 无网络延迟
- ✅ 无交易所处理延迟
- ✅ 订单即时生效
- ⚠️ 与真实交易有差异（真实交易有几毫秒到几百毫秒延迟）

## 🔍 订单状态追踪

### 订单生命周期

```
下单 → onOrderCallback（确认）
  │
  ├─ 立即成交 → onTradeCallback (matchtype='T')
  │
  ├─ 挂单等待 → 等待对手盘
  │     │
  │     └─ 碰到对手盘 → onTradeCallback (matchtype='T')
  │
  └─ 撤单 → onTradeCallback (matchtype='D')
```

### 回调参数说明

**onOrderCallback**:
```python
callback.orderlocalid  # 订单本地ID (OrderLocalID)
callback.time          # 下单时间
callback.exchange      # 交易所 (0=上海, 1=深圳)
callback.direction     # 方向 (1=买, 2=卖)
callback.price         # 下单价格（厘）
callback.volume        # 下单数量
callback.ask1          # 下单时卖一价
callback.bid1          # 下单时买一价
callback.deltapos      # 当前持仓
```

**onTradeCallback**:
```python
callback.localid       # 订单本地ID (OrderLocalID)
callback.matchtype     # 'T'=成交, 'D'=撤单
callback.direction     # 'B'=买, 'S'=卖
callback.volume        # 成交/撤单数量
callback.price         # 成交价格（厘）
callback.matchamount   # 成交金额（元）
callback.deltapos      # 成交后持仓
callback.matchtime     # 成交时间
```

## 📈 持仓计算

引擎自动维护策略持仓：

```
买入成交: 持仓 += 成交数量
卖出成交: 持仓 -= 成交数量
```

通过 `callback.deltapos` 获取最新持仓。

## 🏛️ 沪深市场差异

| 特性 | 上海 (SH) | 深圳 (SZ) |
|------|----------|----------|
| 订单排序 | bizindex | orderid |
| 订单类型 | 仅限价 | 限价/市价/最优五档 |
| 收盘集合竞价 | 14:57-15:00 | 14:57-15:00 |

## ⚠️ 注意事项

1. **无市场冲击**：虚拟订单成交不会改变真实订单簿，适合小资金策略测试
2. **同步成交**：与真实交易的延迟特性有差异
3. **历史数据依赖**：回测结果取决于历史数据质量
4. **涨跌停限制**：引擎会根据前收盘价自动计算涨跌停价格

## 🔧 技术实现

- **语言**: C++ 17 (核心引擎) + Python (策略接口)
- **并行**: Taskflow 框架支持多合约并行回测
- **数据结构**: 树状数组 (Fenwick Tree) 优化集合竞价计算
- **绑定**: pybind11 实现 Python 绑定
